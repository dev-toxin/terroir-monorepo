# Журнал решений (принятых без владельца)

Формат: дата — решение — почему — альтернативы. Любое решение можно пересмотреть; ссылки на этот файл есть в `docs/sessions/`.

## D-001 · 2026-10-02 · Go-директива 1.26, драйвер SQLite modernc v1.60.1
- **Решение:** `go 1.26.0` в `go.mod`, образ compose `golang:1.26`.
- **Почему:** `modernc.org/sqlite@v1.60.1` (есть в локальном кэше) требует Go ≥ 1.26; локально Go 1.26.
- **Альтернативы:** более старый sqlite v1.29 под Go 1.22 — старее, без выигрыша.

## D-002 · 2026-10-02 · Хранилище: SQLite (modernc, без CGO) для dev/тестов + PostgreSQL для боевого
- **Решение:** один SQL-репозиторий поверх `database/sql` с «диалектом» (плейсхолдеры, время), две схемы миграций (`migrations/sqlite`, `migrations/postgres`). `STORAGE=sqlite|postgres|memory`; `memory` = SQLite `:memory:` (не отдельная реализация).
- **Почему:** `make dev` без Docker одной командой; один код запросов на оба движка — меньше расхождений, тесты репозитория реально гоняют SQL. Postgres через `pgx/v5/stdlib`.
- **Альтернативы:** отдельная in-memory реализация на map — третий код, расхождение семантики транзакций; goose — лишняя зависимость ради 2 файлов.

## D-003 · 2026-10-02 · Миграция 000001 переписана, а не 000002
- **Решение:** продакшена нет, данных нет → старая схема сканера заменена новой схемой в `000001_init.sql` для каждого диалекта. Старая версия — в git-истории (коммит `e219f7d`).
- **Почему:** 000002 «удалить всё и создать заново» только запутает. `VECTOR(1536)` убрано (привязка к размерности OpenAI); расширение `vector` в Postgres оставлено в `infra/postgres/init`.
- **Альтернативы:** 000002 поверх старой — бессмысленно без данных.

## D-004 · 2026-10-02 · Идентификаторы TEXT (UUID генерирует приложение), деньги — в минимальных единицах
- **Решение:** `id TEXT` во всех таблицах обоих диалектов; цена — `purchase_price_minor INTEGER` + `currency`; списки (сорта, теги) — JSON в `TEXT`.
- **Почему:** одинаковое поведение в SQLite и Postgres, нет float для денег, не нужен драйверо-специфичный маппинг массивов/uuid.
- **Альтернативы:** `UUID`/`TEXT[]`/`JSONB` в Postgres — лучше индексы, но расходится с SQLite; можно перейти позже миграцией.

## D-005 · 2026-10-02 · Окно питья — в годах
- **Решение:** `drink_from`, `drink_until` — годы (nullable). Статусы: `too_early` (ещё рано), `ready` (пора), `peak` (пик — средняя треть окна), `last_call` (последний год окна), `late` (уже поздно), `unknown`. Текущая дата — через инъекцию часов.
- **Почему:** так думают о вине люди и этикетки («2024–2030»); точные даты не нужны.
- **Альтернативы:** даты — лишняя точность и ввод.

## D-006 · 2026-10-02 · Оценка «выпил» — 1–5
- **Решение:** `rating` 1–5 (целое), 0/пусто — без оценки.
- **Почему:** привычно (Vivino — 5 звёзд), быстро одним тапом на телефоне; «купить снова» = оценка ≥ 4.
- **Альтернативы:** 100-балльная — точнее, но медленнее и непривычно для бытового использования.

## D-007 · 2026-10-02 · Аутентификация MVP — статический Bearer-токен на пользователя
- **Решение:** таблица `user_tokens(token_hash)` (SHA-256), токены задаются через `AUTH_TOKENS=user_id:token,...` или сидом (dev-токены `dev-anton`, `dev-elena`). Без регистрации и паролей. Поле `users.telegram_id` — задел под Telegram login.
- **Почему:** пользователей двое; меньше кода и поверхности атаки.
- **Альтернативы:** OAuth/пароли — избыточно; Telegram login — после выбора клиента.

## D-008 · 2026-10-02 · «Дом» = погреб
- **Решение:** `cellars` + `cellar_members(role owner|member)`. Вина, бутылки и рецепты принадлежат погребу (общие для пары), профиль вкуса, ответы опроса, история «выпил», память чата — пользователю.
- **Почему:** совместный погреб пары — ядро; у каждого свой вкус.
- **Альтернативы:** глобальный каталог вин — нужен позже для импорта/дедупликации, не для двух человек.
